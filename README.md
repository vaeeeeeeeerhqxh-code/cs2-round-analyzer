# Анализ переломных моментов раунда CS2

**Тема для согласования:** «Интерактивный анализ переломных моментов раунда Counter-Strike 2 методами машинного обучения».

## Идея

Модель по текущему состоянию матча оценивает вероятность победы CT. Приложение воспроизводит записанный раунд и показывает, как меняется эта оценка вместе с событиями и позициями игроков. Изменение прогноза рядом с событием само по себе не доказывает причинную связь.

## Что уже сделано

- Загружены реальные состояния раундов из [открытого набора CS2](https://github.com/pnxenopoulos/cs2-win-prob/releases/tag/data%2Ftabular%2Fv1.0.0); файл проверяется по SHA-256 из манифеста автора.
- `train.py` обучает три варианта: простой ориентир, логистическую регрессию и случайный лес. Сохраняет точность и Brier score — ошибку оценки вероятности.
- Матчи в тестовой части не встречаются при обучении. Скрипт явно проверяет это по хешам демок.
- Результаты записываются в `results.json`, `model_comparison.png`, `predictions.csv`; обученная логистическая регрессия — в `model.joblib`.

На текущем запуске получено 23 424 состояния из 271 демки. На тестовых матчах простой ориентир дал accuracy 0,602, логистическая регрессия — 0,771, случайный лес — 0,761. Это результаты первого прототипа, их ещё нужно дополнить анализом ошибок и проверкой отдельных фаз раунда.

Интерфейс `app.py` открывается с картой настоящего матча и выбором раунда. Игроки движутся по координатам из `.dem`, видны здоровье, убийства, установка бомбы, перемотка и скорость воспроизведения. Над картой — прогноз CT/T для каждого кадра, график изменений и сдвиг за последние пять секунд. В текущей локальной демке доступны все 14 раундов. Раздел «Анализ модели» сохраняет прежний прогноз по четырём состояниям из открытого набора.

`train_replay_model.py` обучает отдельную модель на признаках, которые доступны и в таблице, и в `.dem`: время, здоровье, броня, экипировка, гранаты, число погибших и состояние бомбы. Выбор между логистической регрессией и случайным лесом сделан на отдельной валидации по матчам. Выбранная логистическая регрессия дала **76,0% верных классификаций** и Brier score **0,153** на 1 096 состояниях из 12 тестовых матчей. Этот тест не использовался при выборе модели.

## Форматы данных

| Файл | Для чего нужен |
| --- | --- |
| `.dem` | Исходная запись матча CS2. Её можно получить из сохранённого матча и разобрать библиотекой Awpy. Это не видео. |
| `.parquet` | Таблица игровых состояний после обработки демок. Одна строка — состояние матча в определённый `tick`. Эту таблицу используем для обучения. |
| `.csv` | Удобный для просмотра список прогнозов модели (`predictions.csv`). |
| `.joblib` | Сохранённая обученная модель и порядок её признаков. |

Для новой демки работает полная цепочка прототипа: `.dem` → Awpy → координаты и признаки игроков → `replay_model.joblib` → прогноз для каждого кадра → карта с таймлайном. `predict_replay.py` собирает признаки в том же порядке, что при обучении. Признаки оружия и расстояния до бомбы в эту модель пока не включены, чтобы не подставлять приблизительные значения.

Для обучения в таблице есть карта, фаза раунда, время фазы, количество погибших, здоровье, броня, оружие, снаряжение, бомба и некоторые расстояния. `round_end_reason` — правильный ответ. Идентификатор демки и `tick` помогают разделить и найти записи, но не передаются модели как признаки. Координат игроков в обучающей таблице нет: для карты сверху их нужно извлекать непосредственно из `.dem`.

## Запуск прототипа

В PowerShell из этой папки:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe train.py
.\.venv\Scripts\python.exe train_replay_model.py
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Чтобы добавить свой повтор, сначала выполните:

```powershell
.\.venv\Scripts\python.exe extract_replay.py "C:\путь\к\матчу.dem"
```

Без дополнительного параметра скрипт извлечёт **все раунды** и создаст локальный `index.json` для переключателя в интерфейсе. Для одного конкретного раунда добавьте `--round 3`. Файлы повторов и карта сохраняются в `data/local_replays/`, эта папка исключена из Git. Исходная демка тоже не отправляется в репозиторий. Для первой загрузки карты Awpy нужен интернет.

Если окружение `.venv` уже подготовлено, запускайте Streamlit. Обе команды обучения нужны только при переобучении: сохранённые модели уже включены в проект. Понадобится Python 3.12; исходный Parquet уже лежит в `data/`.

В разделе «Анализ модели» график показывает **четыре состояния на раунд** из исходного набора. Карта повтора использует отдельную настоящую `.dem` и позиции игроков с шагом примерно в секунду. Для неё применяется отдельная модель, обученная только на признаках, которые реально извлекаются из `.dem`.
