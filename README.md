# Анализ переломных моментов раунда CS2

**Тема для согласования:** «Интерактивный анализ переломных моментов раунда Counter-Strike 2 методами машинного обучения».

## Идея

Модель по текущему состоянию матча оценивает вероятность победы CT. Приложение будет воспроизводить записанный раунд, показывать эту вероятность на каждом шаге и выделять моменты, когда оценка сильно изменилась. Например, после установки бомбы шанс CT изменился с 52% до 28%. Это изменение оценки модели, а не доказательство того, что одно событие стало единственной причиной исхода.

## Что уже сделано

- Загружены реальные состояния раундов из [открытого набора CS2](https://github.com/pnxenopoulos/cs2-win-prob/releases/tag/data%2Ftabular%2Fv1.0.0); файл проверяется по SHA-256 из манифеста автора.
- `train.py` обучает три варианта: простой ориентир, логистическую регрессию и случайный лес. Сохраняет точность и Brier score — ошибку оценки вероятности.
- Матчи в тестовой части не встречаются при обучении. Скрипт явно проверяет это по хешам демок.
- Результаты записываются в `results.json`, `model_comparison.png`, `predictions.csv`; обученная логистическая регрессия — в `model.joblib`.

На текущем запуске получено 23 424 состояния из 271 демки. На тестовых матчах простой ориентир дал accuracy 0,602, логистическая регрессия — 0,771, случайный лес — 0,761. Это результаты первого прототипа, их ещё нужно дополнить анализом ошибок и проверкой отдельных фаз раунда.

Интерфейс `app.py` теперь открывается с картой настоящего раунда: игроки движутся по координатам из `.dem`, видны здоровье, убийства, установка бомбы, перемотка и скорость воспроизведения. Раздел «Анализ модели» сохраняет прежний прогноз по четырём состояниям из открытого набора. На карте локальной демки вероятность пока не показывается: для этого нужно получить из неё те же признаки, на которых обучалась модель.

## Форматы данных

| Файл | Для чего нужен |
| --- | --- |
| `.dem` | Исходная запись матча CS2. Её можно получить из сохранённого матча и разобрать библиотекой Awpy. Это не видео. |
| `.parquet` | Таблица игровых состояний после обработки демок. Одна строка — состояние матча в определённый `tick`. Эту таблицу используем для обучения. |
| `.csv` | Удобный для просмотра список прогнозов модели (`predictions.csv`). |
| `.joblib` | Сохранённая обученная модель и порядок её признаков. |

Для новой демки уже работает первая часть цепочки: `.dem` → Awpy → координаты игроков и события → карта с таймлайном. Прогноз для неё потребует получить те же признаки, что при обучении. Их смысл и порядок должны совпадать с признаками сохранённой модели.

Для обучения в таблице есть карта, фаза раунда, время фазы, количество погибших, здоровье, броня, оружие, снаряжение, бомба и некоторые расстояния. `round_end_reason` — правильный ответ. Идентификатор демки и `tick` помогают разделить и найти записи, но не передаются модели как признаки. Координат игроков в обучающей таблице нет: для карты сверху их нужно извлекать непосредственно из `.dem`.

## Запуск прототипа

В PowerShell из этой папки:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe train.py
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Чтобы добавить свой повтор, сначала выполните:

```powershell
.\.venv\Scripts\python.exe extract_replay.py "C:\путь\к\матчу.dem"
```

Скрипт сам выберет раунд с событиями. Для конкретного раунда добавьте `--round 3`. Файлы повтора и карта сохраняются в `data/local_replays/`, эта папка исключена из Git. Исходная демка тоже не отправляется в репозиторий. Для первой загрузки карты Awpy нужен интернет.

Если окружение `.venv` уже подготовлено, запускайте Streamlit. `train.py` нужен только при переобучении. Понадобится Python 3.12; исходный Parquet уже лежит в `data/`.

В разделе «Анализ модели» график показывает **четыре состояния на раунд** из исходного набора. Карта повтора использует отдельную настоящую `.dem` и позиции игроков с шагом примерно в секунду. Эти два источника пока не объединены в один прогноз.
